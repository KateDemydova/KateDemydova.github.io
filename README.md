# CRM Клієнтська Система

Це CRM-застосунок на базі React + TypeScript + Express + Mongoose для управління клієнтами.
Дозволяє додавати, редагувати, фільтрувати, видаляти клієнтів, а також відображає статуси та можливість їх змінювати,
VIP-позначки та інформацію про оплату.

## Основні функції

### Frontend

#### Додавання нового клієнта

Форма включає поля:

Ім’я (обов’язкове, мін. 5 символів)

Email (обов’язковий, з перевіркою формату)

Телефон (обов’язковий, з маскою для +380 через react-phone-input-2)

Компанія (необов’язково)

Посада (необов’язково)

VIP-клієнт (чекбокс)

Статус: active, inactive, awaiting_payment, debtor

#### Перевірка на дублікат:

Якщо клієнт з такою ж email-адресою вже існує — з’являється confirm() з повідомленням.

При скасуванні — дані не відправляються.

#### Валідація імені

Ім'я клієнтів потрібно вводити лише кирилицею, для спрощення подальшого пошуку клієнта у базі.
При введенні імені латиницею, поле не пройде валідацію та дані не будуть відправлені.

#### Пошук клієнтів

Реалізовано у компоненті Sidebar, через текстовий пошук за допомогою
searchTerm and setSearchTerm. Це дозволяє керувати станом введення та реагувати на зміни,
внесені користувачем.
Якщо результатів немає — відображається повідомлення "Клієнтів не знайдено"

#### Редагування клієнта

Дані клієнта підтягуються через useParams()

Якщо ID некоректний або клієнта немає — показується повідомлення

Після збереження — перенаправлення на головну сторінку.

#### Видалення клієнта

Дані клієнта видаляються методом onDelete.
Якщо при видаленні виникла помилка, клієнт бачить повідомлення.
Після успішного видалення також є повідомлення про виконання дії.

#### Сторінка оплат

Доступна за шляхом /payments

Виводить клієнтів зі статусами "awaiting_payment", "debtor", "inactive".
Є можливість змінити статус клієнта, якщо він здійснив оплату. При цьому
виводиться повідомлення про зміну статусу та клієнт зникає зі списку оплат.

міститься у `src/types/client.ts`, де описано тип `Client`, `ClientStatus` та допоміжні типи.

## Backend

### ClientModel

Цей файл описує Mongoose-схему для клієнта (Client). Він визначає структуру документа в базі даних MongoDB.

Основні поля:

name (string, обов’язково)

email (string, обов'яково, має бути унікальним і тільки нижнім регістром)

phone (string)

company (string)

amount (number) — сума до сплати

dueDate (Date) — крайній термін сплати

status (string, default: awaiting_payment) — можливі значення: "active", "inactive", "awaiting_payment", "debtor"

### ClientController

Цей файл містить контролери (обробники запитів) для клієнтів. Всі функції є асинхронними та взаємодіють з MongoDB через
модель Client.

Основні контролери:

getClients — отримання списку клієнтів з фільтрацією та пагінацією

getClient — отримання одного клієнта за id

createClient — створення нового клієнта

updateClient — оновлення клієнта за id (через PUT або PATCH)

deleteClient — видалення клієнта

Кожна функція повертає як успішний статус, так і обробляє помилку з відповідним статусом(500 фбо 404).

### ClientRoutes

Цей файл визначає маршрути Express для клієнтів.

Роутинг:

GET /api/clients — отримати всіх клієнтів

POST /api/clients — створити нового клієнта

GET /api/clients/:id — отримати одного клієнта

PUT /api/clients/:id — повне оновлення клієнта

PATCH /api/clients/:id — часткове оновлення (наприклад, лише статус)

DELETE /api/clients/:id — видалити клієнта

Обидва методи PUT і PATCH ведуть до одного контролера updateClient.

### Server

Це головний файл запуску Node.js сервера.

Що тут є:

Імпорти та підключення:

dotenv — для .env файлів

express, cors, morgan — базові middleware

mongoose — підключення до MongoDB

app.use('/api/clients', clientRoutes) — підключення клієнтських маршрутів

Запуск сервера на process.env.PORT або 5000
